Traps found in the Phase 0 spec audit (2026-11-14); re-check them in every later audit (spec amendments, code, tests).

- **Returns examples:** recompute D7 win_loss numbers by hand and check they sum to 0. Phase 0 draft had n=4,k=2 winners at +1/2 (correct is +1/3). Tests copied from examples inherit such errors.
- **5-player Lines +1 vs "power <= 0 does nothing":** the rulebook doesn't say whether the <=0 check is on M-k or on M-k+1 (they differ for the letter where M-k = 0). Was raised as a user question; check what the spec/PLAN §9 now says before auditing code.
- **"Resolve as fully as possible" for Lines:** whether a player may pick an extension that dead-ends both ends while another sequence would place every unit (greedy vs lookahead). Vrrooomm! is safe (count = min, always reachable greedily); Passengers/Buildings are unit-independent.
- **Stations have no sites**, but passengers placed there CAN be carried into buildings by Vrrooomm!. Watch for wording/tests saying they "never enter a building".
- **Roundabouts hold 8 of the 12 tier-A sites** (board.yaml), so the C3 ⚑ "starting passengers don't step in before a Clock" default actually matters in play.
- **Move-number origin (R-062/R-070):** ACTIONS defines move number = OpenSpiel history length, but scenario-loaded states carry `last_score_move` from before the load; unless an offset is defined the tiebreak can invert. Check this in scenario loader code/tests.
- **"Occupied" is overloaded:** street occupied (has a marker, R-013), building occupied (has a passenger, R-062, SCENARIOS `occupied`), and R-049/R-066 "every site is occupied" (= built). Sites-full code/tests must test "every site has a building", not passengers.
- **Phase 0 close (2026-11-14):** spec R-001..R-073 audited PASS; previously-fixed items: R-033 (+1 before <=0), R-040/R-042 maximal Lines resolution, R-039 overlap cases, R-071 example. Layout block verified against map render (action spaces, 5 stones, score 1-20, clock clockwise house->office->pub); bus_grid only 20 cells (backlog).
- **Line geometry (Phase 1 unit 4, 2026-11-14, PASS):** O-2 "earlier marker counts as occupied" is a no-op for the owner's own pure-geometry check (own streets are already excluded by R-037), so geometry-level "sequential" tests can't fail; the real O-2 test is state-level (units 2..p of one Lines marker see the updated line). R-039(c) is implied by (d), so same-arrival counter-example tests are vacuous but faithful. Board has no parallel streets (validated), which is what makes ACTIONS 1.3 orientation unambiguous; re-check if board.yaml changes. A random-line property check vs an own oracle (grow lines via extend, track the node walk independently) ran in under a minute and is worth repeating for line code.
- **Resolution driver (Phase 1 unit 7, 2026-11-14, PASS in scope):** order/power/Buses/skips were right. Recurring trap: phase hand-offs that set `current` directly (e.g. `end_round` -> next SEL `current=start`) bypass the R-027 skip, so a seat with 0 Action markers gets SEL actions and markers go negative. Check every transition into SEL/resolution goes through the same "next active seat" logic. Also watch `units_left` set to raw power when supply (passengers, Bus Line markers, sites) is smaller: an encoding choice, not a rule, but tests/dumps must agree.
- **Maximal Lines resolution (Phase 1 unit 8, 2026-11-14, PASS):** memo on (own line tuple, depth) is sound only because other seats' lines are static within one marker; re-check if lookahead ever spans markers/seats. Random fixtures rarely bite (~2% of random positions), so a property check needs thousands of positions (~2 s for 12k at depth <= 6; scratch script pattern: own geo oracle + brute DFS, no memo). Recurring traps: (1) the scenario loader accepts phase LN/PX/BD states whose node has zero legal actions (non-terminal, no actions) although ACTIONS says such nodes are never emitted; (2) `pending("R-0xx")` markers left on tests that really wait on a later unit (e.g. tagged R-042 but blocked by PX/R-045), which /close-phase will misreport.
- **Clock / last stone (Phase 1 unit 10, 2026-11-14, PASS):** movement and stone logic right (20k-position oracle check of move_passengers + 400 random engine games, 0 mismatches). Recurring trap: an **immediate** END (last stone, mid-round) leaves the action board, cursor etc. as they were, but SCENARIOS S-BOARD forbids a non-empty board in END, so `load(dump(s))` fails for a reachable terminal state. Check every END path (unit 12 too) against the loader's validation, not just clone/serialize. Board fact: at most 2 sites per node (roundabouts 13/17/18/21 hold sites 2-7, 9-10), so spec examples with 3 buildings at one node can't be built as fixtures; tests split them across nodes.
- **Vrrooomm! (Phase 1 unit 11, 2026-11-14, PASS):** forced count, canonical DELIVER, move numbers (incl. move_offset) all right; 3.3k markers in 1.5k random engine games + 3k random-position exhaustive DFS (every leaf scores exactly the forced count, never blocked), 0 mismatches. Recurring trap again: the unit-3 loader fixtures for a phase (`resolve_vp`, `resolve_vd`) were built before the phase's rules and turn out to be dead ends (VD with no legal DELIVER); the INV fixture test's "phase not implemented yet -> skip" then hides them silently (the suite's 1 skip). After each unit, check that the skip count drops and the phase's own `resolve_*` fixture has legal actions. Also: with the unit-12 stub, once every seat has 0 markers, SEL offers only DROP_OUT forever (round +1 per move); random sims must stop on "all markers 0" or they burn the cap; check unit 12 removes this.
- **Game end / scoring (Phase 1 unit 12, 2026-11-14, PASS):** end_round, round_end_types, winners, returns_for all literal to R-064..R-072; 1.5k random engine games (all three end types, k=1..5 shared wins) vs own oracle (own move-number tracking, Fraction returns), 0 mismatches. Recurring traps: (1) the loader never checks `end.types` against the END state, so hand-built END fixtures (unit-3 `end_*` and `tests/scenarios/end/*`) claim `sites_full` with empty sites, `markers` with every seat holding 20, or `sites_full` with 0 stones on the clock; harmless for scoring tests, but check any test that reads end types from a loaded fixture. (2) Fields the dump omits but the observation string prints (`cur=` in END) make `str(load(dump(s))) != str(s)` although the dumps match; check obs-string equality, not just dump equality, in round-trip checks. (3) `resolve_vd` INV skip from unit 11 was still present at unit 12.
- **Phase 1 close (2026-11-14, PASS):** whole-engine round-driver oracle (scratch `oracle.py`: own setup order, cyclic-pointer SEL passes, resolution queue with shadow buses, per-marker node counts, skip justification, round-end start player/end types, last stone) ran 4k random games x 3 policies (uniform / drop-heavy / build-heavy / pause-heavy) in ~1 min, 0 mismatches; plus load(dump(s)) at every node of 300 games (57k nodes), 0 mismatches. Reuse both at later phase closes. Oracle trap: snapshot buses at round START, not after the last SEL action (the engine already ran automatic Buses before the first node). Recurring nit: docstrings citing the wrong rule ID (R-046 on Buildings code); grep `Implements R-` against function purpose. Coverage grep must use `R-?0XX([^0-9]|$)`, since `\b` misses `test_R003_` (underscore is a word char).
- Random sims stop at the first unimplemented phase (e.g. `stuck_VP`); count how many reach the phase under audit before trusting "slow tests pass".
- Tiebreak "most time stones wins" is literal rulebook (counter-intuitive); don't flag it as a bug.

**Why:** these are where the rulebook is thin or where the arithmetic is easy to get wrong.
**How to apply:** grep for R-033, R-040, R-046, R-071 (or their successors) and verify each point first. See also [[rulebook-layout]].
